# 《数字识图闯关》需求文档 V1.0

> 来源：基于《数字列车》需求分析报告中"关卡一（看图数数→选数字）"的改进重做，独立成新游戏。
> 适用：一年级上册 · 10以内数的认识（含 0）· 数数对应
> 形态：单文件 HTML（`小学一年级/数字识图闯关.html`），零依赖离线可用，大屏/触屏/鼠标适配
> 核心玩法：**左右两队 PK · 看图数数 · 数字键盘直接输入 · 答对放烟花闯下一关**

------

## 一、对原"关卡一"的改进点（为什么这么改）

| 原关卡一 | 本游戏改进 | 理由 |
|---|---|---|
| 点圆圈 → 再选数字，两步完成 | **数字键盘直接输入**，一步到位 | 两步式对会写数字的孩子是重复劳动；直接输入更贴近"数→认→写"的教学闭环 |
| 单人单题 | **左右两队 PK，各自独立出题** | 小组竞赛是低年级课堂最强激励；两队题面独立避免"抄答案" |
| 未说明含不含 0 | 明确 **0~10，含 0**（空盘子表示 0） | 教材要求"0 表示一个也没有"，必须练 |
| 题量/通关未定义 | **开局可设置题目数量**（3~30，默认 10） | 老师按课堂时间自由控制 |
| 答对无庆祝 | **答对触发烟花特效** | 即时正反馈拉满 |

------

## 二、游戏流程

```
设置页：老师设定题目数量（默认10） → 点「开始闯关」
   ↓
PK页：左队（🍓红队） / 右队（🍎蓝队） 同时开始
   每队各自：图片题（数一数）→ 数字键盘输入 → ✓提交
   ├─ 答对：烟花绽放 + 音效 + 「答对啦」→ 1秒后自动下一题
   └─ 答错：轻提示音 + 摇晃 + 「再数一数」→ 修改后重新提交（不惩罚不限次）
   ↓
先答完全部题目的队伍 → 🏆 通关横幅；两队都完成后 → 结算弹窗（各队用时/错误次数）
   ↓ 「再来一局」「返回设置」
```

------

## 三、功能规格

### 3.1 设置页
- 题目数量：数字输入（范围 3~30，默认 10），两队共用同一数量
- 队名可编辑（默认：🍓 红队 / 🍎 蓝队）
- 「开始闯关」按钮

### 3.2 出题规则（每队独立随机）
- 每题：随机类别（水果/蔬菜/动物）→ 随机一种图案 → 随机数量 **0~10**
- 图案池：水果 🍎🍌🍇🍓🍊🍉🍍、蔬菜 🥕🥦🍅🌽🍆🥬、动物 🐱🐶🐰🐸🦋🐔🐠🦁
- 排布：每行最多 5 个、最多两行，随机轻微偏移/旋转（活泼但不影响计数，参考看图说数字的排布原则）
- **数量 0 的表示**：只显示一个空盘（虚线圆盘 + "空空的盘子"），孩子答 0——对应教材"0 表示一个也没有"
- 同队相邻两题不重复同一图案

### 3.3 数字键盘与作答
- 键盘布局（电话式大按钮）：`1 2 3 / 4 5 6 / 7 8 9 / ⌫ 0 ✓`
- 输入显示：大号数字框（最多 2 位）
- 提交时机：按 ✓ 提交；输入满 2 位（只能是"10"）自动提交
- 判定：答对 → 烟花 + 下一题；答错 → 摇晃 + 轻提示音 + 计错误数，**必须答对才进入下一题**（不限次数）
- 300ms 防连点

### 3.4 烟花特效
- 答对时在该队题面上方绽放一组放射彩色粒子（20+颗），配"啵嘤"上行音效
- 每队通关时全屏连续烟花 + 🏆 横幅

### 3.5 结算
- 双队完成后弹窗：每队 用时 / 错误次数 / 🏆 获胜方（先完成者）
- 错误次数仅展示不排名惩罚

## 四、界面布局

```
顶栏：标题「🔢 数字识图闯关」· 题目进度（第x/N题）· 音效开关 · 重新设置
主区：左队面板 ｜ 右队面板（各含：队名/进度/错误数/图卡/输入框/键盘）
```

- 队伍主色：红队 #e84393 / 蓝队 #0984e3；背景糖果渐变
- 图卡高约 34vh，图案字号大、对比强；键盘按钮 ≥70px 高

------

## 五、边界与异常

1. 输入超过 2 位自动截断；⌫ 退格修改
2. 空输入按 ✓ 无效（输入框轻微提示）
3. 数量 0 的题面：必须仍可作答（答 0），不得出现"没有图案没法数"的歧义（空盘+文字引导）
4. 一队先通关后另一队可继续完成（不强制结束），结算在双队完成后弹出
5. 刷新即重置（不持久化，课堂公用机防脏数据）

------

## 六、验收清单

- [ ] 设置题量 5/10/20 均可正常开局
- [ ] 0~10 数量均会出现，0 显示空盘且可答对
- [ ] 两队出题互不影响，进度独立
- [ ] 答对烟花+音效+自动下一题；答错可重试且计错误数
- [ ] 10 的输入（两次按键）可正确判定
- [ ] 先通关队伍出现 🏆，双队完成后出现结算
- [ ] 触屏点击热区充足，300ms 防抖
- [ ] 离线可用，无任何外部请求
